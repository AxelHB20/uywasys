G. ACTUALIZAR: PRIMERO LA PRUEBA, DESPUES LA CLINICA
----------------------------------------------------
La prueba tiene su propia API y su propia web. PRUEBA_IMAGE_TAG en el .env decide su version
(sin esa linea, usa la misma que la clinica). Cambia v0.4.4 por la version nueva.

G1. PC (H:\uywasys) - publicar la version nueva:
git add -A; git commit -m "Descripcion del cambio"; git tag v0.4.4
git push; git push --tags
powershell -ExecutionPolicy Bypass -File .\deploy\publicar-imagenes.ps1 -Owner axelhb20 -Tag v0.4.4
  (si cambio docker-compose.server.yml o deploy\sites\prueba.caddy, copialos con scp)

G2. SERVIDOR - actualizar SOLO la prueba:
uywa exec backup backup.sh
sed -i '/^PRUEBA_IMAGE_TAG=/d' ~/uywa/.env
echo 'PRUEBA_IMAGE_TAG=v0.4.4' >> ~/uywa/.env
uywa pull prueba-api prueba-web && uywa up -d
uywa exec -e DEMO_REFRESH=1 prueba-api node scripts/demo-data.mjs

G3. Revisar en https://prueba-veterinario.duckdns.org que todo funcione.

G4. SERVIDOR - si todo esta bien, actualizar la clinica:
sed -i 's/^IMAGE_TAG=.*/IMAGE_TAG=v0.4.4/' ~/uywa/.env
uywa pull && uywa up -d

Si algo fallo en G3: la clinica nunca se toco. Se corrige, se publica otra version y se repite.
OJO: la prueba necesita v0.4.3 o mas nueva. No pongas PRUEBA_IMAGE_TAG en una version anterior.
