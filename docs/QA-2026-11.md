# Revisión de calidad (QA) — noviembre 2026

Revisión antes de la prueba piloto. Se probó con la demo (clínica "Veterinaria Huellitas") y con una
clínica de **volumen** generada con ~3 años de una veterinaria mediana (~40 atenciones/día).

## Resumen

| Área | Resultado |
|---|---|
| Aislamiento entre clínicas | **Sin fugas.** 86 rutas probadas con IDs de otra clínica (lectura, cambios y referencias dentro del cuerpo): ninguna devolvió datos ni aplicó cambios. |
| Permisos por rol | Según lo esperado. 1 corrección (vacunas, abajo). |
| Recorrido de pantallas | 5 roles × escritorio y celular × 39 pantallas (390 vistas): **0** errores de consola, 0 respuestas de error inesperadas, 0 desbordes horizontales, 0 textos "undefined"/"NaN". |
| Rendimiento con 3 años de datos | Todas las pantallas por debajo de 150 ms. 1 optimización (vacunas por vencer: 58,8 → 2,0 ms). |
| Migraciones | Las 23 migraciones se aplican limpias en una base vacía y las 154 pruebas e2e pasan sobre ella. |
| Respaldo y restauración | Respaldo cifrado de 13 MB en 2 s; restauración en base temporal en 7 s con los mismos conteos en 19 tablas. |
| Pruebas automáticas | Backend 117 unitarias + 154 e2e, frontend 172, Playwright 4 (flujos de punta a punta). |

## Hallazgos y correcciones

| # | Gravedad | Hallazgo | Corrección |
|---|---|---|---|
| 1 | Media (legal) | Recepción podía registrar una vacuna **aplicada en la clínica** (en la atención, o como "aplicada aquí"): el carnet la mostraba firmada por recepción, sin CMVP. | Solo veterinario o administrador registran una vacuna aplicada aquí; recepción solo antecedentes de otra clínica. El botón "Aplicar" de la atención ya no aparece para recepción. Prueba e2e. |
| 2 | Baja | El estado y la desactivación del portal de un cliente de **otra** clínica respondían 200/204 (sin datos ni efecto). | Ahora 404, como cualquier ficha ajena. |
| 3 | Rendimiento | "Vacunas por vencer" (inicio y recordatorios) ordenaba todo el historial de vacunas de la clínica en cada consulta: crece con los años. | Busca solo las vacunas que vencen en el rango y comprueba fila a fila que sea la última aplicación, con el índice `immunizations_latest_idx`. Resultado idéntico verificado; 58,8 → 2,0 ms; inicio 109 → 70 ms. |
| 4 | Producción | La prueba mensual de restauración (`verify.sh`) solo comparaba 9 tablas: no revisaba comprobantes, vacunas, recetas, citas, archivos ni el portal. | Compara 19 tablas. |

## Cómo repetir la revisión

```bash
# 1. Clínica de volumen (solo bases locales de prueba)
psql $DATABASE_URL -f backend/scripts/qa/volume.sql
# 2. Con la API corriendo (node dist/main):
node backend/scripts/qa/qa-perf.mjs          # EMAIL=qa-admin-<id>@uywa.pe
node backend/scripts/qa/qa-tenant.mjs        # DATABASE_URL, CLINIC_B=<otra clínica>, EMAIL, PASSWORD
node backend/scripts/qa/qa-roles.mjs         # usuarios demo de Huellitas
node e2e/qa-recorrido.cjs                    # también necesita ng serve
```
